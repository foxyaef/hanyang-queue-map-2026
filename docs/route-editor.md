# 관리자 동선 편집과 복구

## 사용 방법

1. `/admin/`에서 로그인하고 장소를 선택한 뒤 **지도 동선 편집**을 누릅니다. 기존 대기 현황에 미저장 변경이 있다면 먼저 저장합니다.
2. **점 이동**: 지도 위 점을 드래그합니다. 아래 구간·점 선택 상자와 방향 버튼으로도 세밀하게 이동할 수 있습니다. 첫 수령처·게이트 점은 고정입니다.
3. **점 추가**: 선택한 점 다음 위치를 지도에서 누릅니다. 마지막 점을 선택하면 동선을 연장합니다.
4. **새 구간**: 통행 공간 건너편 시작 위치를 누른 다음 다음 점을 추가합니다. 각 구간에 최소 두 점이 필요합니다. **다음 점 사이 비우기**는 선택한 점과 그 다음 점을 잇는 선을 제거하고 두 구간으로 나눕니다.
5. **모서리 보정**은 꺾이는 부분만 작게 둥글립니다. 도로를 자동 추론하거나 무조건 도로 가운데로 이동시키지는 않습니다. 원래 확정 동선은 편집 전 그대로 유지됩니다. 처음 편집할 때는 조작하기 쉽도록 1.5 지도 단위 오차 안에서 제어점을 줄입니다.
6. 건물·도로 경고를 확인합니다. 경고는 현재 그림의 좌표와 선 두께 기준의 보조 검사이며 지리정보/현장 안전 검증이 아닙니다. 주차장 등 정당한 도로 밖 경로는 현장 확인 체크 후 적용할 수 있습니다. 다른 대기열과의 충돌까지 자동 판정하지는 않습니다.
7. **줄 끝 지정**으로 실제 끝에 가까운 지도 위치를 누르거나 아래 흰색 바를 움직입니다. 새 동선에서는 같은 수치라도 위치가 달라지므로 줄 끝 확인 체크가 필수입니다.
8. **임시 저장**은 DB에 편집 초안만 저장하며 공개되지 않습니다. 현재 줄 길이는 임시 저장하지 않으므로 다시 열었을 때 재확인합니다. **공개 적용**은 동선과 현재 길이를 함께 저장합니다. 사용자 페이지는 다음 새로고침 시 한 번의 API 호출로 함께 불러옵니다.

실행 취소·다시 실행은 현재 편집 세션의 최근 40단계입니다. 임시 동선은 장소별 하나이며 관리자가 공유합니다. 동시에 수정한 경우 이전 내용을 덮어쓰지 않고 새로 불러오도록 안내합니다. 점 편집은 화면의 지도 영역 안으로 제한됩니다. 지도 밖 확장은 지도 자체의 범위를 먼저 수정해야 합니다.

## 지도 동선만 복구

**저장된 동선 / 이전 버전 복구**를 펼쳐 과거 버전 또는 **기본 지도 동선으로 되돌리기**를 선택합니다. 줄 끝 확인 후 공개 적용해야 실제 복구됩니다. 과거 이력을 삭제하지 않고 새 버전으로 추가합니다. 최근 50개를 화면에 표시하며 DB 이력은 남습니다. 복구 시 운영시간·입장 마감 여부는 변경하지 않습니다.

- 이전 배포로 복귀할 때는 사용자 요청을 확인한 후, 현재 DB를 새로 백업하고 Cloudflare의 배포 롤백을 사용합니다. Git 작업 사본에 다른 변경이 있다면 별도 worktree에서 태그를 빌드합니다. `reset --hard`로 사용자의 작업을 없애지 마세요.
- 기존 프로그램은 DB 동선을 읽지 않으므로 복귀 직후에는 기존 지도 기준으로 각 줄 끝을 다시 확인해야 합니다. 백업 레코드를 자동 덮어쓰면 이후 운영 현황을 잃을 수 있으므로 요청 없이 복원하지 않습니다.

## 개발 구조

- `shared/route.ts`: 숫자 좌표 검증, 단순화, 보정, 구간별 누적 길이. 0~1000은 구간 사이 빈 통행 공간을 제외한 전체 동선의 비율입니다.
- `app/maps/route-registry.ts`: 여섯 지도의 기존 좌표계, 고정 시작점, 도로/건물 검사. 좌표계 변경 시 저장 동선도 함께 버전 이전해야 합니다.
- `app/route-editor.tsx`: 편집기. 기존 로그인 인증을 사용하며 비밀번호를 저장하지 않습니다.
- `backend/migrations/0002_route_editor.sql`: 추가형 마이그레이션. 이미 적용한 파일을 수정하지 말고 이후 변경은 새 번호로 추가합니다.
- `GET /api/v1/queues`: 각 항목에 `route`(기본은 null)와 `routeRevision`(기본은 0)을 추가합니다. HTTP 조회 횟수는 그대로 한 번입니다.
- `GET /api/v1/admin/queues/:id/route`: 인증 후 현재 현황, 임시 동선, 최근 50개 이력.
- `PATCH /api/v1/admin/queues/:id/route`: `action: draft | publish`, `route`, `expectedRevision`; 임시 저장은 `expectedDraftAt`, 공개 적용은 `expectedUpdatedAt`, `queueValue`, 필요 시 `acknowledgeWarnings`.
- 공개 적용도 `expectedDraftAt`을 검사합니다. 편집 중 다른 관리자가 임시 동선을 저장했다면 해당 초안을 지우지 않고 409로 중단합니다.
- 현재 길이 수정 API에도 `expectedRouteRevision` 및 `expectedUpdatedAt`을 보냅니다. 이미 동선이 바뀐 뒤 구버전 화면에서 저장하면 409로 거절합니다. 새로고침해 최신 지도를 읽으세요.
- 버전 삽입 트리거에서 버전/시각을 재검사하고 같은 SQL 문장의 트랜잭션 안에서 길이 갱신·초안 제거를 수행합니다. 동선만 저장되고 길이가 이전 상태로 남는 부분 저장을 방지합니다.

## 검증

`node scripts/check-route-editor.cjs`: 운영 DB를 건드리지 않는 실제 SQLite 기반 검증. 여섯 동선 × 1001개 길이, 빈 구간 제외, 인증, 좌표 검증, 임시 저장 비공개, 동시 수정, 공개 적용, 복구를 검사합니다.

`node scripts/check-route-worker.cjs`: `127.0.0.1:8793`의 별도 로컬 Wrangler/D1 테스트 서버 전용입니다. 운영 주소로 바꾸지 마세요. 공개 서버의 대기 길이를 시험 목적으로 수정하지 않습니다.
